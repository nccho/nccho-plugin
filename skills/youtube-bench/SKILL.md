# YouTube Bench

유튜브 게임 영상을 yt-dlp + ffmpeg로 캡처해 **벤치마킹 자료집**(마크다운 보고서 +
선별 프레임)을 만든다. 전략은 2-pass: 저해상 그리드로 전체를 훑어 관심 장면을
찾고, 그 시점만 고해상으로 정밀 추출한다.

## 원칙 (먼저 읽기)

- **개인 벤치마킹·연구 용도의 단건 분석에만** 사용한다. 캡처물은 내부 참고 자료이며
  재배포·재업로드하지 않는다.
- 라이브 스트림·멤버십·연령제한 영상은 지원하지 않는다. 다운로드 실패 시 사유만
  정직하게 보고하고 중단한다.
- 다운로드 원본 영상은 임시 폴더에만 둔다. **산출물은 보고서와 프레임뿐**이다.
- 사용자가 벤치마킹 초점(예: "인벤토리 UI 위주")을 줬으면 그 기준으로 장면을
  고르고, 없으면 전반(UI/전투/연출/진행 구조)을 고르게 훑는다.

## 1. 사전 점검

```powershell
Get-Command yt-dlp, ffmpeg
```

둘 중 하나라도 없으면 설치 안내 후 **중단**한다:
`winget install yt-dlp.yt-dlp` (ffmpeg가 의존성으로 함께 설치됨. 설치 후 새 셸
필요 — 현재 셸에서 안 잡히면 `%LOCALAPPDATA%\Microsoft\WinGet\Links\` 절대경로 사용).

## 2. 메타데이터 확인 + 다운로드 (임시 폴더)

```bash
yt-dlp --no-playlist --print "%(title)s|%(duration)s|%(height)s" "<URL>"
```

제목에서 폴더용 slug(소문자-하이픈, 영숫자만)를 만들고, 길이로 그리드 간격을
정한다: **10분 미만 5초, 10~30분 10초, 30분 이상 15초**.

```bash
yt-dlp --no-playlist -f "bv*[height<=1080][ext=mp4]/bv*[height<=1080]/b[height<=1080]" \
  -o "<임시폴더>/video.%(ext)s" "<URL>"
```

프레임만 필요하므로 video-only 스트림(`bv*`)을 우선한다(오디오 병합 불필요, 다운로드
절반 이하). 화질 상한 1080p. mp4 스트림이 없으면 webm 등 다른 확장자로 받아질 수
있다 — 다운로드 후 실제 파일 경로를 확인하고, 이후 단계의 `<영상파일>` 자리에 그
경로를 쓴다.

## 3. 1-pass: 저해상 그리드 훑기

출력 폴더는 현재 프로젝트의 `docs/research/benchmark/<slug>/`다(구조는 §5).
ffmpeg는 출력 폴더를 만들어주지 않으므로 **`grid/`·`frames/` 하위 폴더를 먼저
생성**한 뒤 실행한다. 5x5 타일 시트로 만들어 Read 횟수를 줄인다. 타임스탬프를 각
셀에 새긴다:

```bash
ffmpeg -i "<영상파일>" -vf "fps=1/<간격>,drawtext=text='%{pts\:hms}':fontfile='C\:/Windows/Fonts/arial.ttf':fontsize=28:fontcolor=yellow:box=1:boxcolor=black@0.6,scale=384:-1,tile=5x5" -q:v 5 "<출력폴더>/grid/grid_%03d.jpg"
```

- drawtext가 실패하면(폰트 문제 등) 그 부분만 빼고 재실행하고, 타임스탬프는 셀
  인덱스로 계산한다 — 시트 k는 **1부터**, 행 r·열 c는 **0부터** 센다:
  `((k-1)*25 + r*5 + c) * 간격` 초. 예: 시트 2의 첫 셀(r=0, c=0) = `25 * 간격` 초.
- 시트를 Read로 훑으며 벤치마킹 초점에 맞는 장면의 타임스탬프를 목록으로 만든다
  (장면당 "타임스탬프 + 무엇이 보이는지 한 줄"). 통상 8~20개가 적당하다.

## 4. 2-pass: 고해상 정밀 캡처

선정한 타임스탬프마다 원본 해상도로 1장씩 뽑는다. `-ss`를 `-i` 앞에 두면 시킹이
빠르다:

```bash
ffmpeg -ss <hh:mm:ss> -i "<영상파일>" -frames:v 1 -q:v 2 "<출력폴더>/frames/<hhmmss>_<라벨>.jpg"
```

라벨은 장면 내용(예: `013045_inventory-grid.jpg`). 뽑은 프레임을 Read로 확인해
장면이 어긋났으면(전환 중 블러 등) ±1~2초로 재추출한다.

## 5. 보고서 작성

산출물 구조(§3에서 만든 출력 폴더):

```text
docs/research/benchmark/<slug>/
├── report.md      # 분석 보고서
├── grid/          # 1-pass 그리드 시트 (전체 개관용)
└── frames/        # 2-pass 고해상 선별 프레임
```

`report.md` 구성: 영상 정보(제목/URL/길이) → 벤치마킹 초점 → 장면별 분석(고해상
프레임을 `frames/...` **상대경로로 참조**하고, 프레임마다 무엇을 배웠는지·우리
게임에 어떻게 적용할지 기록) → 종합 시사점. 분석은 시각 정보 기반으로만 쓰고
추측은 추측이라고 밝힌다.

## 6. 마무리

- 임시 폴더의 다운로드 영상을 삭제한다(보고서·프레임만 보존).
- 보고서 경로와 핵심 시사점 3줄 요약을 사용자에게 보고한다.
- 이 프로젝트처럼 `docs/STATUS.md`/연구 인덱스 관례가 있는 저장소라면 인덱스 갱신을
  제안한다(강제하지 않는다).
